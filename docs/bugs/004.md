# Substitute with a line range beyond EOF raises uncaught `IndexError`

**Category:** robustness · **Area:** `pyvim/commands/commands.py` (`substitute`) · **Found at:** deep review, hg rev 164 (2026-11-06)

## Summary

The substitute command converts the captured range (`range_start`, `range_end`)
straight into document line numbers without validating them against the number
of lines in the buffer; an out-of-document line index reaches prompt_toolkit's
`Buffer.transform_lines` and raises.

## Evidence

* [`pyvim/commands/commands.py:715-722`](../../pyvim/commands/commands.py):
  `get_line_index_iterator` converts `int(range_start) - 1` (and
  `int(range_end) - 1`) with **no** upper-bound check against
  `document.line_count`.
* `:s` is dispatched from [`pyvim/commands/handler.py:44-46`](../../pyvim/commands/handler.py)
  with the grammar-captured range (`grammar.py:15`) — no validation there
  either.
* Measured probe (Python 3.15.2): with a 3-line buffer,
  `handle_command(":900s/one/xyz")` raises
  `IndexError: list index out of range` — an uncaught application crash, not a
  message.

## Impact

Any `:<n>s/…` with `n` greater than the line count (easy typo; ranges are
commonly used after editing shrinks the file) terminates the editing session
with a traceback instead of a message.

## Fix direction

Validate the converted range against `doc.line_count` and call
`editor.show_message(...)` (vim shows `E16: Invalid range`-style feedback)
when it is out of bounds; clamp `range_end` to the last line only if vim-like
leniency is desired.
