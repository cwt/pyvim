# Duplicate code and logic inventory (round 2: duplicated comment block, `ENCODINGS` loop, `FileIO()` instantiation, redundant filter, active buffer lookup)

**Category:** duplicate code / logic · **Area:** `pyvim/key_bindings.py`, `pyvim/io/backends.py`, `pyvim/editor.py` · **Found at:** deep review, hg rev 191 (2026-11-07)

## Summary

Five instances of duplicated code or logic were identified at hg rev 191:

1. **Verbatim duplicated 3-line comment banner in `pyvim/key_bindings.py:197-203`**[^src-kb]:
   ```python
   # Cell-cluster Vi editing and motion overrides (Phase 3):
   # step/delete/change by whole cell clusters (base + combining marks)
   # rather than single codepoints.

   # Cell-cluster Vi editing and motion overrides (Phase 3):
   # step/delete/change by whole cell clusters (base + combining marks)
   # rather than single codepoints.
   ```
2. **Duplicated `ENCODINGS` decode loop in `pyvim/io/backends.py`**[^src-io]:
   `FileIO.read` (`pyvim/io/backends.py:38-46`) re-opens the file from disk for each encoding in `ENCODINGS`, duplicating `_auto_decode(data: bytes)` (`pyvim/io/backends.py:165-173`) used by `GZipFileIO` and `HttpIO`. Reading the raw `bytes` once in `FileIO.read` and calling `_auto_decode(raw_bytes)` eliminates the duplicate loop and avoids reading the file from disk twice for non-UTF-8 files.
3. **Repeated `FileIO()` instantiation in `GZipFileIO`** ([`pyvim/io/backends.py:66-70`](../../pyvim/io/backends.py)[^src-io]):
   `GZipFileIO.can_open_location` and `GZipFileIO.exists` instantiate a throwaway `FileIO()` object on every call (`FileIO().can_open_location(location)`, `FileIO().exists(location)`). `GZipFileIO` can either subclass `FileIO` or delegate to a shared module-level helper.
4. **Redundant `& ~vi_waiting_for_text_object_mode` filter composition** ([`pyvim/key_bindings.py:283, 304, 311`](../../pyvim/key_bindings.py)[^src-kb]):
   In `prompt_toolkit.filters.app`, `vi_navigation_mode` already checks `vi_State.operator_func is None` (which is the exact inverse of `vi_waiting_for_text_object_mode`). Combining `vi_navigation_mode & ~vi_waiting_for_text_object_mode` evaluates the same condition twice per key event.
5. **Linear scan in `Editor.current_editor_buffer` vs `WindowArrangement.active_editor_buffer`** ([`pyvim/editor.py:215-225`](../../pyvim/editor.py)[^src-ed], [`pyvim/window_arrangement.py:233-236`](../../pyvim/window_arrangement.py)[^src-wa]):
   `Editor.current_editor_buffer` linearly scans `self.window_arrangement.editor_buffers` comparing `eb.buffer == current_buffer` instead of returning `self.window_arrangement.active_editor_buffer` in $O(1)$ (falling back to the buffer scan only when focus is in a non-editor toolbar buffer).

## Fix direction

1. Remove the duplicate comment block at `pyvim/key_bindings.py:201-203`.
2. Reuse `_auto_decode` inside `FileIO.read`.
3. Subclass `FileIO` in `GZipFileIO` or extract a module-level `_is_local_file_location` helper.
4. Drop the redundant `& ~vi_waiting_for_text_object_mode` conjunction on `vi_navigation_mode` bindings.
5. Check `self.window_arrangement.active_editor_buffer` first in `Editor.current_editor_buffer`.
