# `mypy.ini` pins `python_version=3.15` while the project floor (and AGENTS.md rule) is 3.10

**Category:** compatibility / governance · **Area:** `mypy.ini` · **Found at:** deep review, hg rev 164 (2026-11-06)

## Evidence

* [`mypy.ini:3`](../../mypy.ini): `python_version = 3.15`.
* The Thai plan's own verification record states 3.10 was the checked target
  (`mypy --python-version 3.10` + `ast.parse(..., feature_version=(3, 10))`,
  see [`thai_support_plan.md §5.1`](../thai_support_plan.md)).
* Recent audit scan: every module still parses under 3.10 grammar — no
  >3.10 syntax exists today; the config simply no longer *enforces* the floor
  (3.11+ only constructs, e.g. `typing.Self`, `except*`, `StrEnum`, would
  typecheck green).
* Project coding rules (AGENTS.md, "Coding Style") demand strict ≤3.10 usage
  unless the project explicitly requires newer.

## Impact

Nothing is broken today; the gate silently loosened, so future 3.11+ syntax
will pass the configured check while violating the documented rule.

## Fix direction

Set `python_version = 3.10` in `mypy.ini` (and re-run `mypy .` to confirm the
clean baseline stays clean).
