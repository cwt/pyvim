# `setup.py` lacks `python_requires` and modern packaging metadata

**Category:** packaging · **Area:** `setup.py` · **Found at:** deep review, hg rev 164 (2026-11-06)

## Evidence

* [`setup.py:10-31`](../../setup.py): no `python_requires`, and the declared
  matrix implied by [.travis.yml](../../.travis.yml) (2.7/3.5/3.6) contradicts
  the codebase (3.10-verified per docs, PEP 604/585 annotations in
  `__future__` modules, Python 3.14/3.15 fixes baked in).
* `long_description=long_description` without
  `long_description_content_type='text/x-rst'`.
* `install_requires` includes `six` only as py2 residue — see
  [027](027.md).

## Impact

pip on Python 2.6/2.7 or otherwise incompatible interpreters happily installs
a package that cannot run; advisory metadata for the 3.10 floor is missing.

## Fix direction

Add `python_requires='>=3.10'` (drop with the six removal in
[027](027.md)), add `long_description_content_type='text/x-rst'`, and keep
`packages=find_packages('.')`.
