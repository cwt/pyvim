# `six` dependency and py2 `__future__` imports are pure legacy weight

**Category:** legacy · **Area:** several modules · **Found at:** deep review, hg rev 164 (2026-11-06)

## Evidence

* `six` usages:
  [`setup.py:21`](../../setup.py) (install_requires),
  [`pyvim/io/backends.py:6-7`](../../pyvim/io/backends.py) (`six.moves.urllib`),
  [`pyvim/editor_buffer.py:10`](../../pyvim/editor_buffer.py) (`string_types`),
  [`pyvim/window_arrangement.py:9`](../../pyvim/window_arrangement.py)
  (`string_types`),
  [`pyvim/reporting.py:15`](../../pyvim/reporting.py) (`assert … six.string_types`),
  [`pyvim/commands/commands.py:7` + `227`](../../pyvim/commands/commands.py)
  (`six.moves.input`),
  [`pyvim/rc_file.py:13-14`](../../pyvim/rc_file.py) (`string_types`,
  `six.exec_`, `six.moves.input`).
* `from __future__ import unicode_literals` appears in **26 modules** — no
  effect on Python 3.
* The PTK2-only branches (`pyvim/editor_buffer.py:17-23`) exist to support
  the `prompt_toolkit>=2.0.0` lower bound that both 2026 plans effectively
  abandoned (they target and test prompt_toolkit 3.0.53).

## Impact

Extra required dependency for nothing; reader noise implying dual-version
support that is no longer real.

## Fix direction

Replace `string_types` → `str`, `six.moves.input` → `input`,
`six.exec_` → `exec(…, namespace, namespace)`, urllib via
`urllib.request`; drop `six` from `install_requires`; remove the
`from __future__ import unicode_literals` lines; decide on the
PTK2-era compatibility branches (keep or drop the `prompt_toolkit>=3.0`
floor per plan reality).
